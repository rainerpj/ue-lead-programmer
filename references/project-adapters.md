# Project Adapters

Load an adapter only when repository-specific authority, build, compatibility, or asset rules matter to the task. Match by project identity; never by genre alone.

- [TopDownRoguelikeShooter](../adapters/topdown-roguelike-shooter.md)

## Use

Read the matching adapter and only the live files relevant to the current decision. Do not scan every project index, task, or configuration directory on routine edits.

Live project authority takes precedence over stale adapter facts. Verify inexpensive facts that affect the current action, such as the engine version before building. If no adapter matches, use the live project without creating a persistent adapter.

## Maintenance

Update an adapter only when a confirmed durable change affects its guidance, such as an engine migration, build entrypoint, authority location, ownership boundary, or delivery convention. A full adapter audit is not required at every task start.

Keep transient task status, branch state, defects, test results, tuning values, and asset selections in the appropriate project records. Do not duplicate general workflow or safety rules here.

When changing an adapter, preserve unrelated guidance, verify referenced paths, and report the source of the changed rule.
